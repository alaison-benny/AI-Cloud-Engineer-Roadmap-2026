# Kubernetes: Imperative vs Declarative Methods ☸️

Kubernetes ക്ലസ്റ്ററിലെ ഒബ്‌ജക്റ്റുകളെ (Pods, Services etc.) എങ്ങനെയെല്ലാം മാനേജ് ചെയ്യാം?

## 📖 Overview

പ്രധാനമായും There are 2 methods to manage cluster objects:
1. **Imperative Commands**: ക്ലസ്റ്ററിനോട് നേരിട്ട് നിർദ്ദേശങ്ങൾ നൽകുന്ന രീതി.
2. **Declarative Approach**: ഡിസൈർഡ് സ്റ്റേറ്റ് (Desired State) നിർവ്വചിച്ച് നൽകുന്ന രീതി.

---

## 1. Imperative Commands (നേരിട്ടുള്ള നിർദ്ദേശങ്ങൾ)

ക്ലസ്റ്ററിലെ റിസോഴ്സുകൾ ക്രിയേറ്റ് ചെയ്യാനോ, മാറ്റം വരുത്താനോ, ഡിലീറ്റ് ചെയ്യാനോ നേരിട്ട് കമാൻഡുകൾ നൽകുന്ന രീതിയാണിത്.

* **പ്രധാന ലക്ഷ്യം**: കോൺഫിഗറേഷൻ ഫയലുകളെക്കാൾ ഉപരിയായി പെട്ടെന്നുള്ള ഫലത്തിന് മുൻഗണന നൽകുന്നു.
* **ഗുണം**: പെട്ടെന്നുള്ള പരീക്ഷണങ്ങൾക്കും (Troubleshooting) ലളിതമായ കാര്യങ്ങൾക്കും വളരെ എളുപ്പമാണ്.
* **ദോഷം**: കോൺഫിഗറേഷനുകൾ ട്രാക്ക് ചെയ്യാത്തതിനാൽ 'Configuration Drift' ഉണ്ടാകാൻ സാധ്യതയുണ്ട്. അതായത്, നമ്മൾ വരുത്തിയ മാറ്റങ്ങൾ എവിടെയും റെക്കോർഡ് ചെയ്യപ്പെടാത്തതിനാൽ പിന്നീട് അത് ഓർത്തെടുക്കാൻ പ്രയാസമായിരിക്കും.

### 🛠 ഉപയോഗിക്കുന്ന പ്രധാന കമാൻഡുകൾ:
* `kubectl run <pod-name> --image=<image-name>`: ഒരു പോഡ് വേഗത്തിൽ ക്രിയേറ്റ് ചെയ്യാൻ.
* `kubectl create`: പുതിയ റിസോഴ്സുകൾ ഉണ്ടാക്കാൻ.
* `kubectl replace`: നിലവിലുള്ള റിസോഴ്സിനെ മാറ്റാൻ.
* `kubectl delete`: ഒരു റിസോഴ്സിനെ നീക്കം ചെയ്യാൻ.

## 2. Declarative Approach (പ്രഖ്യാപന രീതി)

Kubernetes ക്ലസ്റ്റർ മാനേജ് ചെയ്യാൻ ഏറ്റവും Ideal രീതിയാണിത്. ഇവിടെ നമ്മൾ ഒരു ഫയലിലൂടെ (YAML അല്ലെങ്കിൽ JSON) ക്ലസ്റ്ററിന് എന്താണ് വേണ്ടതെന്ന് പറഞ്ഞു കൊടുക്കുന്നു.

* **പ്രവർത്തന രീതി**: നമ്മൾ നൽകുന്ന YAML ഫയലിലെ 'Desired State'-ഉം ക്ലസ്റ്ററിലെ നിലവിലെ 'Current State'-ഉം തമ്മിൽ Kubernetes താരതമ്യം ചെയ്യുന്നു. എന്തെങ്കിലും വ്യത്യാസമുണ്ടെങ്കിൽ അത് സ്വയം പരിഹരിച്ച് നമ്മൾ ആവശ്യപ്പെട്ട രീതിയിലേക്ക് ക്ലസ്റ്ററിനെ മാറ്റുന്നു.
* **ഗുണം**: എല്ലാ മാറ്റങ്ങളും ഫയലുകളിൽ ഉള്ളതിനാൽ ഭാവിയിൽ റെഫറൻസിനായി ഉപയോഗിക്കാം (Version Control).

### 🛠 ഉപയോഗിക്കുന്ന പ്രധാന കമാൻഡ്:
* `kubectl apply -f <filename.yaml>`: ഈ കമാൻഡ് ഉപയോഗിച്ചാണ് നമ്മൾ ഡിക്ലറേറ്റീവ് രീതിയിൽ കോൺഫിഗറേഷൻ ഫയലുകൾ റൺ ചെയ്യുന്നത്.
