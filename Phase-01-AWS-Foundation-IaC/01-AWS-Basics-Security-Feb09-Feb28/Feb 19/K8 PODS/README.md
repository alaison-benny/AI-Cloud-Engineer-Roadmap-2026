# കുബെർനെറ്റീസ് പോഡുകൾ 
ഈ പ്രമാണത്തിൽ കുബെർനെറ്റീസ് പോഡുകളെക്കുറിച്ചുള്ള അടിസ്ഥാന വിവരങ്ങളും അവ നിയന്ത്രിക്കാൻ ആവശ്യമായ പ്രധാന കമാൻഡുകളും ഉൾപ്പെടുത്തിയിരിക്കുന്നു.

## പോഡ് (Pod) എന്നാൽ എന്ത്?
കുബെർനെറ്റീസിലെ ഏറ്റവും ലളിതമായ യൂണിറ്റാണ് പോഡ്. ഒന്നോ അതിലധികമോ കണ്ടെയ്നറുകൾ (ഉദാഹരണത്തിന് Docker containers) ഒരുമിച്ച് പ്രവർത്തിക്കുന്ന ഒരു പാക്കേജ് പോലെയാണിത്. ഇവ ഒരേ നെറ്റ്‌വർക്കും സ്റ്റോറേജും പങ്കിടുന്നു.

## പ്രധാന കുബെർനെറ്റീസ് കമാൻഡുകൾ (Important Kubernetes Commands)

താഴെ പറയുന്ന കമാൻഡുകൾ ഉപയോഗിച്ചാണ് പോഡുകളെ നിയന്ത്രിക്കുന്നത്:

| കമാൻഡ് (Command) | വിശദീകരണം (Description) |
| :--- | :--- |
| `kubectl run <pod-name> --image=<image>` | ഒരു പുതിയ പോഡ് വേഗത്തിൽ നിർമ്മിക്കാൻ ഉപയോഗിക്കുന്നു (Imperative approach). |
| `kubectl get pods` | ക്ലസ്റ്ററിൽ നിലവിലുള്ള എല്ലാ പോഡുകളുടെയും പട്ടിക കാണാൻ. |
| `kubectl get pods -o wide` | പോഡുകളുടെ ഐപി അഡ്രസ്സ്, അവ പ്രവർത്തിക്കുന്ന നോഡ് എന്നിവയുൾപ്പെടെയുള്ള കൂടുതൽ വിവരങ്ങൾ അറിയാൻ. |
| `kubectl describe pod <pod-name>` | ഒരു നിശ്ചിത പോഡിനെക്കുറിച്ചുള്ള മുഴുവൻ വിവരങ്ങളും (Events, IP, Containers) അറിയാൻ. |
| `kubectl logs <pod-name>` | പോഡിന്റെ ലോഗുകൾ (Logs) പരിശോധിക്കാൻ. |
| `kubectl logs <pod-name> -c <container-name>` | മൾട്ടി-കണ്ടെയ്നർ പോഡാണെങ്കിൽ ഒരു പ്രത്യേക കണ്ടെയ്നറിന്റെ ലോഗുകൾ കാണാൻ. |
| `kubectl exec -it <pod-name> -- bash` | ഒരു പോഡിനുള്ളിൽ പ്രവേശിച്ച് കമാൻഡുകൾ നേരിട്ട് പ്രവർത്തിപ്പിക്കാൻ. |
| `kubectl apply -f <file.yaml>` | ഒരു YAML ഫയൽ ഉപയോഗിച്ച് പോഡ് നിർമ്മിക്കാനോ നിലവിലുള്ളതിൽ മാറ്റം വരുത്താനോ (Declarative approach). |
| `kubectl delete pod <pod-name> --now` | ഒരു പോഡിനെ പെട്ടെന്ന് നീക്കം ചെയ്യാൻ. |
| `kubectl explain pod.spec.restartPolicy` | റീസ്റ്റാർട്ട് പോളിസികളെക്കുറിച്ചുള്ള കൂടുതൽ വിവരങ്ങൾ അറിയാൻ. |

## റീസ്റ്റാർട്ട് പോളിസികൾ (Restart Policies)
പോഡുകൾ എപ്പോൾ വീണ്ടും തുടങ്ങണം എന്ന് തീരുമാനിക്കുന്നത് ഈ പോളിസികളാണ്:
* **Always:** കണ്ടെയ്നർ എപ്പോൾ നിന്നാലും അത് വീണ്ടും പ്രവർത്തിപ്പിക്കും (Default).
* **OnFailure:** കണ്ടെയ്നർ തകരാർ (Error) മൂലം നിന്നാൽ മാത്രം വീണ്ടും പ്രവർത്തിപ്പിക്കും.
* **Never:** കണ്ടെയ്നർ ഒരിക്കലും താനേ റീസ്റ്റാർട്ട് ആകില്ല.

## ഇംപറേറ്റീവ് vs ഡിക്ലറേറ്റീവ് (Imperative vs Declarative)
* **Imperative:** `kubectl run` പോലുള്ള കമാൻഡുകൾ വഴി നേരിട്ട് പോഡുകൾ നിർമ്മിക്കുന്നത്. ഇത് പെട്ടെന്നുള്ള കാര്യങ്ങൾക്ക് നല്ലതാണ്.
* **Declarative:** `YAML` ഫയലുകളിൽ പോഡിന്റെ ഘടന എഴുതി `kubectl apply` വഴി നടപ്പിലാക്കുന്നത്. ഇതാണ് പ്രൊഫഷണൽ രീതിയിൽ കൂടുതൽ ഉപയോഗിക്കുന്നത്.

## സൈഡ്കാർ കണ്ടെയ്നർ (Sidecar Container)
പ്രധാന കണ്ടെയ്നറിനെ സഹായിക്കാൻ മറ്റൊരു കണ്ടെയ്നർ കൂടി ഒരേ പോഡിൽ ഉപയോഗിക്കുന്ന രീതിയാണിത്. ഉദാഹരണത്തിന്, ലോഗുകൾ ശേഖരിക്കാനോ ഹെൽത്ത് ചെക്ക് ചെയ്യാനോ സൈഡ്കാർ കണ്ടെയ്നർ ഉപയോഗിക്കാം.

---
*കുറിപ്പ്: ഭാവി പഠനത്തിനായി ഈ കമാൻഡുകൾ പരീക്ഷിച്ചു നോക്കുന്നത് നന്നായിരിക്കും.*
